# UX-прототип: Маркетплейс выставочной индустрии

Чёрно-белый кликабельный frontend-прототип MVP маркетплейса выставочной индустрии.

## Запуск проекта

```bash
cd exhibition-black-and-white
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000)

Production-сборка:

```bash
npm run build
npm start
```

## Стек

- **Next.js 16** (App Router)
- **TypeScript**
- **Tailwind CSS** (только grayscale)
- **Lucide Icons**
- **Zustand** + localStorage (persist)
- Локальные mock-данные (без backend)

## Демо-роли

Используйте меню **«Демо (инструмент прототипа)»** в левом нижнем углу:

| Роль | Описание |
|------|----------|
| Заказчик | Создание заявок, сравнение откликов, сделки |
| Исполнитель | Отклики на заявки, проекты, выплаты |
| Площадка | Залы, схема размещения, бронирования |
| Организатор | Создание мероприятий, участники |

Также доступны:
- **Сбросить mock-данные** — полный сброс состояния
- **Вернуть исходные статусы** — восстановление seed-данных

## Структура маршрутов

### Публичная зона
- `/` — главная
- `/how-it-works` — как работает сервис
- `/events`, `/events/[id]`, `/events/[id]/booking` — каталог мероприятий
- `/contractors`, `/contractors/[id]`, `/contractors/[id]/check` — исполнители
- `/services`, `/services/[id]` — услуги
- `/cart`, `/checkout` — корзина и оформление

### Авторизация
- `/login`, `/register`, `/forgot-password`, `/verify`, `/moderation`

### Сквозные модули
- `/requests`, `/requests/new`, `/requests/[id]` — заявки
- `/requests/[id]/responses`, `/compare`, `/respond` — отклики
- `/deals/[id]` — сделки
- `/documents`, `/payments` — документы и оплаты
- `/notifications`, `/messages`, `/messages/[id]` — уведомления и чат

### Личные кабинеты
- `/account/customer/*` — 17 разделов
- `/account/contractor/*` — 16 разделов
- `/account/venue/*` — 13 разделов
- `/account/organizer/*` — 14 разделов

## Основные сценарии

1. **Регистрация заказчика:** Главная → Регистрация → ИНН → ЭДО → Модерация → Вход → Дашборд
2. **Открытая заявка:** Создать заявку → ТЗ → Публикация → Отклики → Сравнение → Сделка
3. **Закрытая заявка:** Каталог исполнителей → Закрытый запрос → Приглашения → Выбор
4. **Срочный заказ:** Срочная форма → Быстрый отклик → Подтверждение
5. **Покупка услуги:** Каталог → Корзина → Checkout → Безопасная сделка → Оплата → Приёмка
6. **Работа исполнителя:** Доступные заявки → Отклик → Смета → Проект → Выплата
7. **Мероприятие и площадь:** Каталог → Бронирование → Схема → Заказ
8. **Организатор:** Создание мероприятия → Участники → Бронирования
9. **Спор:** Сделка → Замечания → Спор → Решение → Завершение

## Ограничения mock-прототипа

- Нет реального backend, API, ФНС, банка, ЭДО, платёжных систем
- Все реквизиты и названия компаний вымышленные
- Интеграции имитируются через setTimeout и localStorage
- Гант и схема площадки — UX-упрощения, не production
- Админ-панель и B2C-продажа билетов отсутствуют (не в MVP sitemap)

## Состояние данных

Ключевое состояние сохраняется в localStorage:
- Авторизация и профиль
- Корзина
- Заявки, отклики, сделки (изменения)
- Уведомления, сообщения, бронирования
- Черновики регистрации и заявок
