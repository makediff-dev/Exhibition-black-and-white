# Словарь сущностей

Доказательства: аудит №4, 14, 23; playbook §6.1; типы в `src/data/types/index.ts`; подписи в `src/constants/statuses.ts`.

Правило: карточка и детальная страница всегда показывают **тип + стабильный ID + исходный объект**. Запрещено вести разные заказы на одну заглушку (`/deals/deal-1`).

Английские коды (`signed`, `pending`, `reserved`) — машинные. В UI — только русские `label` из контракта статуса.

---

## Канонические сущности

| Код | Пользовательское имя | Назначение | Не подменять | Сейчас в коде |
|---|---|---|---|---|
| `request` | Заявка | Запрос заказчика на предложения от исполнителей | Заказом, сделкой, услугой каталога | `Request`. Статусы: draft / published / in_progress / completed. Нет expired / archived |
| `proposal` | Отклик | КП конкретного исполнителя по заявке | Сообщением, счётом | Интерфейс `Response`. Статусы: pending / accepted / rejected. Нет draft / withdrawn / expired |
| `service` | Услуга | Публичное предложение исполнителя с ценой и условиями | Заявкой заказчика | `Service`. Нет жизненного цикла черновик / модерация / опубликовано |
| `order` | Заказ | Выбранный предмет покупки между конкретными сторонами | Универсальной оболочкой для пропуска, аренды и заявки | Отдельного типа нет. Ближе всего `EventOrder` + опциональный `dealId` |
| `deal` | Сделка | Исполнение согласованного **заказа услуг исполнителя**: этапы, оплаты, приёмка | Заявкой или бронированием | `Deal`. Стороны только customer + contractor. Нет venue/organizer как сторон |
| `booking` | Бронирование | Согласование и резерв площади на периоды монтажа / проведения / демонтажа | Мероприятием или сделкой | `Booking`. Статусы: pending / confirmed / rejected. Нет reserved / expired / cancelled |
| `event` | Мероприятие | Событие организатора; к нему крепятся брони и заказы | Бронированием зала | `Event`. Площадка — строка `venue` + `venueId`, не обязательно согласованная бронь |
| `invoice` | Счёт | Уникальное платёжное требование: номер, плательщик, получатель, объект, сумма | Проводкой или резервом | Отдельного типа нет. Смешано в `Payment` с `type: "Счёт к оплате"` |
| `payment` | Платёж / проводка | Факт движения или резерва средств по счёту | Счётом | `Payment`. Типы: «Резерв», «Выплата», «Счёт к оплате». Зеркальные записи без пары |
| `document` | Документ | Файл/форма: тип, стороны, статус подписи, связь с объектом | Глобальным списком без сторон | `Document`. `parties` — свободная строка; `status` EN; ложные `venueId`/`organizerId` в seed |

## Связанные, но не канонические объекты

| Код | Имя | Роль | Ограничение |
|---|---|---|---|
| `event_order` | Заказ мероприятия | UI-список заказов площадки/организатора (`EventOrder`) | Временный фасад. Целевой объект — `order` своего `type` |
| `venue_inquiry` | Запрос площадке | Черновой подбор площадки до брони | Не бронь и не заказ. Статусы в `VENUE_INQUIRY_STATUS_LABELS` |
| `cart_item` | Позиция корзины | Локальный набор услуг с известной ценой | Не заявка. См. D-03 |
| `floor_cell` | Ячейка плана | Место на схеме | Не бронь, пока нет `booking` |
| `deal_stage` | Этап сделки | Часть исполнения `deal` | Не отдельный заказ |
| `company` / `profile` | Организация | Юридическое лицо с одной активной ролью в сессии (временно, D-01) | `CompanyProfile.role` — одно значение |
| `employee` | Сотрудник | Доступ внутри организации | Права UI-only, входа сотрудника нет |

## Форматы заявки (не сущности)

Это **способ заключения**, не тип объекта.

| Код | Подпись (`REQUEST_FORMAT_LABELS`) | Смысл |
|---|---|---|
| `open_request` | Открытый запрос предложений | Публичная заявка; лимит первых откликов — как в текущем копирайте (10) |
| `closed_request` | Закрытый запрос предложений | Только `invitedContractorIds`, не более 5 |
| `urgent` | Срочная сделка | Короткая форма, ускоренный подбор |
| `safe_deal` | Безопасная сделка | Оплата через резерв платформы |

## Запрещённые смешения (аудит №23)

| Если пользователь видит | Это не |
|---|---|
| Заявка | Заказ и не сделка |
| Отклик | Счёт |
| Заказ на пропуска / аккредитацию | Сделка строительства стенда |
| Бронирование зала | Сделка `deal-1` |
| Резерв | Второй экземпляр того же счёта |
| Документ «Заказчик — Исполнитель» | Документ площадки только потому что в seed стоит `venueId` |

## Контракт подписи статуса в UI

Каждый объект со статусом отдаёт интерфейсу поля из playbook §6.3 (`ActionableStatus`): `code`, `label` (RU), `explanation`, `nextActor`, `deadline`, `allowedActions`, `blockedReason`, `recoveryActions`. Реализация — на этапе 3; имена полей можно адаптировать под TypeScript проекта, смысл — нет.

## Экраны → сущность (минимум для gate)

| Маршрут / раздел | Сущность | Источник истины |
|---|---|---|
| `/requests`, `/requests/new`, `/requests/[id]` | `request` | store `requests` / seed |
| `/requests/[id]/respond` | `proposal` | store `responses` |
| `/services/[id]` | `service` (+ опционально путь в `cart` или `request`) | store `services` |
| `/account/*/active-projects`, `/deals/[id]` | `deal` | store `deals`. **Не** для пропуска/аренды без своего `deal` |
| `/account/{venue\|organizer}/orders` | `order` (сейчас `EventOrder`) | `SEED_EVENT_ORDERS` |
| `/account/venue/bookings`, `/events/[id]/booking` | `booking` | store `bookings` + `floorCells` |
| `/events/[id]`, `/account/organizer/events` | `event` | `SEED_EVENTS` / store events |
| `/account/*/payments` | `invoice` + `payment` (сейчас один `Payment`) | store `payments` |
| `/account/*/documents` | `document` | store `documents` |
| `/account/organizer/venues` | `venue_inquiry` + контекст `event` | `organizerEventDraft` **не** равен списку мероприятий |
| `/account/customer/my-events` | `event` + основание (`request` / `booking` / `order` / favorite) | сейчас смешение без основания |
